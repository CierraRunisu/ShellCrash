## 当前启用的自动行为

- `local_heal=ON`：每 **2 分钟**检查一次进程/控制接口及需要的本地引擎。
- USB 未挂载时等待，不在空挂载点下新建数据，也不在线转换回退。启动阶段最多等待 30 秒；USB 恢复后重新尝试恢复依赖。
- 原有手动停止命令会记录停止意图，自愈不把它当故障；关闭自启动标记时，不启动已停止的内核。
- 自愈失败会退避，连续三次未恢复则暂停，需在菜单 5 中确认重新允许恢复。
- `local_maintenance=ON`：每日首次维护创建配置快照、执行备份轮换、限制超大引擎日志和补丁日志。
- 每类备份默认保留最新 **3 份**，受保护的回滚备份可额外保留；诊断包保留最新 5 份。
- 只轮换本维护中心创建并标记的目录，不删除之前的历史备份、订阅缓存或规则缓存。至少过期约 48 小时的已标记、非活动下载暂存会清理。
- 内置盘低于 5 MiB 时给状态和维护日志提示；官方更新包、压缩过程和备份均在 USB 暂存。

没有开启定时自动升级版本。你选择菜单 3 或原来的官方 Mihomo 更新入口时才执行安全更新；原有自动更新核心任务若启用，也转到安全更新器。

## 安全核心更新与回滚

安全更新器只支持官方 Mihomo 稳定版。自定义核心链接及其他内核不包含在官方资产校验承诺内。

更新顺序：

1. 通过验证证书的 HTTPS 读取 GitHub 官方 Release JSON，作为数据解析，绝不 source。
2. 匹配设备架构与固定官方资产 URL，要求官方提供有效 SHA-256；缺失摘要就停止。
3. 版本比较阻止自动降级；已经是目标版本时不下载、不重启。
4. 核验本地 UPX 的登记 SHA-256，下载、解压和 UPX -9 压缩均在 USB 完成。
5. 执行 UPX 完整性、版本和现有配置兼容性检查。
6. 核验旧核心备份；备份摘要另存内置 `local/backup-index.tsv`，避免仅修改 USB 文件及其同目录摘要就能通过回滚校验。
7. 计算磁盘空间，等待旧进程真正退出后切换；内置盘不足以同时放两个核心时，由已核验的 USB 备份保护替换。
8. 确认实际版本、规则加载、本地引擎以及代理 HTTP 204 连通性。切换或健康检查失败就恢复旧核心；回滚自身无法完成时明确报告备份位置，保留人工恢复资料。

回滚不会任意覆盖后来修改的订阅/密码。旧核心不兼容当前配置时会拒绝回滚。磁盘损坏、USB 物理丢失等可能同时破坏恢复条件，不能把自动回滚当作任何故障下都必然成功的保证。

## 安全向导的边界

目前**没有自动修改控制密钥、代理认证、监听地址、SSH 密码或全局证书设置**。这些动作需要你在菜单里选择，避免影响现有面板连接。

生成新密钥会显示一次并保存到受保护备份目录，要求你保存后自行重启服务；等待生效期间，不因旧接口拒绝新密钥而自动重启。

仅本地模式 `sub_only=ON` 和现有转换策略保持不变。服务恢复不会将订阅交给公共转换服务。
